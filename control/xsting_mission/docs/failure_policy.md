# 실패·예외 처리 원칙

xsting_mission에서 로봇 행동이 실패하거나 예상과 다를 때 누가, 어떻게 처리하는지 정한다.
가짜 경기장, 실물 로봇, 다른 팀이 만드는 로봇 쪽 구현이 모두 이 원칙을 따른다.
에러 코드별 예상 원인, 기대하는 행동, 필요한 이유는 [error_codes.md](error_codes.md)에 적었다.
결과 형식(에러 코드, 필드)은 로봇 명령 규약(지금은 `xsting_mission/core/contract.py`, JSON 스키마로 옮길 예정)에 적는다.

확정: 2026-11-11

## 정해진 값

| 항목 | 값 | 이유 |
|---|---|---|
| 미션 시간 한도 | **30분** | 배터리 사용 시간 |
| 같은 행동 연속 실패 상한 | **3번** | 넘으면 다른 선택을 해야 한다 |
| 하차 박스에 놓은 퍽 다시 옮기기 | **허용 안 함** | 놓은 퍽은 그대로 둔다 |

## 원칙

### 1. 실패는 그것을 가장 잘 아는 층에서 처리한다

| 층 | 맡는 실패 | 하지 않는 것 |
|---|---|---|
| 로봇 | 같은 동작을 다시 하면 풀리는 짧은 실패 (집기 재시도, Nav2 복구 동작, 자리를 바꿔 다시 보기), 위치 추정 복구 | 다른 장소로 가기, 순서 바꾸기 같은 미션 판단 |
| 중계 노드 | 형식·규칙 위반(규약, 나눠 놓기, cell), 로봇 연결 끊김·응답 없음, 같은 실패 반복, 시간 한도 | 대안 고르기 |
| AI | 미션 차원의 대안: 다시 시도, 미루기, 순서 바꾸기, 마무리하고 복귀 | 로봇 내부 재시도 흉내 |

- 에러 코드는 무슨 일이 일어났는지 알리는 정보다. 어떻게 할지는 받는 쪽(중계 노드, AI)이 정한다.
- 설정·버전 문제처럼 다시 보내도 같은 실패(`UNKNOWN_COMMAND`, 로봇의 `BAD_ARGS`)는 AI에게 넘기지 않고 중계 노드가 멈춘다.
- 로봇이 동작했는지 모르는 실패(LOAD·UNLOAD의 `BAD_RESULT`, `TIMEOUT`)는 다시 하지 않고 멈춘다.
- 위치 추정 복구에 실패하면(`LOCALIZATION_LOST`) AI가 도울 방법이 없으므로 중계 노드가 멈춘다.

### 2. 로봇은 할 수 있는 만큼 처리한 뒤, 남은 실패를 숨기지 않고 넘긴다

- **스스로 다시 해 보기**: 행동마다 정해 둔 횟수만큼 다시 한다.
  - 집기 2번, Nav2 복구 동작, 인식이 안 되면 자리를 바꿔 다시 보기
  - 신호등을 못 찾으면 한 바퀴 돌며 찾기, 읽은 신호가 규칙에 안 맞으면(못 읽은 칸, 12개 아님, 끝 소등 못 봄, 색마다 1~6개 아님) 다음 주기를 다시 읽기 (최대 3번, 중간 오류는 로그만)
  - 위치 추정을 잃으면 재위치 추정과 장소 AprilTag로 복구하고, 복구되면 하던 행동을 계속한다
- **안전한 상태로 정리**: 바퀴를 멈추고 팔을 접는다. 집던 퍽은 적재함에 넣거나 내려놓아 그리퍼에 든 채로 끝나지 않게 한다.
  하드웨어 이상이면 비상 정지부터 한다.
- **있는 그대로 알리기**: 그래도 안 되면 반드시 실패로 돌려준다. 성공처럼 보이게 하거나 조용히 건너뛰지 않는다.

### 3. 실패 결과에는 "무엇이 일어났고, 지금 어떤 상태인지"가 반드시 있다

모든 실패 결과에 넣는다.

- `error`: 정해진 에러 코드 중 하나 (예: `OBSTACLE_BLOCKED`, `GRASP_FAILED`, `PLACE_FAILED`)
- `robot`: 지금 위치(`here`, `pose`)와 그리퍼·팔 상태
- 부분 결과: 어디까지 했는지 (실은 퍽, 놓은 항목, 멈춘 위치). 일부 성공도 상태에 그대로 반영한다.
- 원인을 아는 경우 그 정보: 예를 들어 장애물에 막혔으면 장애물 위치와 대략 크기.

### 4. 모르는 것은 모른다고 기록하고, 정답으로 쓰지 않는다

- 인식이 불확실한 값(퍽 색·모양, 신호 색)은 "모름"으로 남긴다. AI는 이를 할당에 쓰지 않는다.
- 로봇 위치를 모르면 `here=UNKNOWN`. 위치 조건이 필요한 행동 전에 먼저 GOTO로 위치를 확정한다.

### 5. 되돌릴 수 없는 행동은 확실할 때만 한다

- 하차 박스에 놓은 퍽은 다시 옮기지 않는다. 그래서 UNLOAD는 규칙 검사(나눠 놓기, cell)를 통과하고 할당이 확정됐을 때만 한다.
- VERIFY_LOCATION에서 불일치가 나와도 퍽을 고치지 않는다. 결과를 기록하고 다음 일을 한다.
- 실패 직후에 급하게 다른 하차를 하지 않는다.

### 6. 같은 실패를 끝없이 반복하지 않는다

- 같은 행동(같은 인자)이 3번 연속 실패하면, 중계 노드가 상태에 "다른 선택을 하라"는 표시를 넣는다.
  그다음 같은 행동이 오면 로봇에 보내지 않고 거절한다.
- 전체 판단 횟수 상한(`max_turns`)은 최후의 안전장치로 둔다.

### 7. 시간이나 방법이 없으면 점수를 지키며 마무리한다

- 미션 시간은 30분이다. 중계 노드가 남은 시간을 상태에 넣고, AI는 HOME 복귀에 필요한 시간을 남겨 둔다.
- 우선순위는 점수표를 따른다 (신호 12, 횟수 9, 바코드 4, 배정 9, 색·모양 18, 눈 배치 30, 재검증 8, 복귀 10).
  이미 얻은 점수를 잃지 않는 쪽을 먼저 고른다.
- 해결이 안 되는 퍽이나 장소는 뒤로 미루고 나머지를 먼저 한다.
- 그래도 안 되거나 시간이 부족하면, 놓을 수 있는 만큼 놓고 검증한 뒤 HOME에 복귀한다.

### 8. 모든 실패는 재현할 수 있어야 한다

- 실패와 대처는 판단 기록에 모두 남긴다 (에러, 부분 결과, 위치, AI가 고른 대안).
- 가짜 경기장의 실패 주입은 시나리오에 적고, 지난 판 다시 실행 때 같은 시점에 같은 실패가 나게 한다.

## 진행 순서

1. 로봇 명령 규약을 JSON 스키마로 옮기고, 실패 결과 형식(에러 코드, 위치, 부분 결과, 장애물 정보)을 넣는다.
   에러 코드 목록은 [error_codes.md](error_codes.md)를 `config/contract/errors.yaml`로 옮긴다.
   나중에 ROS 타입 액션으로 옮기기 쉽게, 필드 타입 하나로 고정, null 대신 "모름" 값, 에러 코드는 한곳에 모은다.
2. 가짜 경기장 실패 주입 장치와 기본 실패 (GOTO 장애물 막힘, LOAD 일부 실패·인식 불확실, UNLOAD 중간 실패).
3. 중계 노드: 연속 실패 상한(3번), 남은 시간(30분)을 상태에 넣기. 프롬프트에 대처 규칙.
4. 마무리 전략 (미루기, 시간 부족 시 복귀)과 VERIFY 불일치 처리.
5. 실물 연결: Nav2 실패를 같은 에러 코드로 바꾸고, 멈춘 위치를 TF로 채우기. 위치 추정 복구(cuVSLAM 재위치 추정, AprilTag).
