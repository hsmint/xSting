OpenCR 한 대에 **3족 × 관절 3개 = 모터 9개**를 연결한다.
`mk1_arm`의 USB DYNAMIXEL Slave / 모터 Sync Read·Write 구조를 사용한다.

- 다리 1: ID `1, 2, 3`
- 다리 2: ID `4, 5, 6`
- 다리 3: ID `7, 8, 9`
- USB Slave ID `200`, 모터 통신 `1 Mbps`, Protocol `2.0`
- 위치 제어 모드 `3`, 목표 위치 `0~4095` (모터 자체의 위치 제한도 적용됨)
- `mk1_arm`과 같은 X-series 제어 테이블 사용. 모터 ID/통신 속도는 미리 설정해야 한다.

설정과 주소는 `include/xSting.h`에 있다. Arduino IDE에서 `mk2_motor.ino`를
열고 OpenCR 보드와 Dynamixel2Arduino 라이브러리로 빌드한다.

<a id="section-1"></a>

## 파일 구성

- `src/xSting.cpp`: `ControlItemVariables`, USB 제어 테이블, Heartbeat, 항목별 `update_*()`
- `src/motor_driver.cpp`: `xStingMotorDriver`, 관절 데이터 구조체, `read_present_*()`·`write_*_joint()`
- `src/sensor.cpp`: 내장 IMU, 배터리 전압, 버튼, 범퍼, 사용자 LED, 비동기 부저 재생
- `src/diagnosis.cpp`: 동작·USB 송수신·호스트 연결 LED, 저전압 경고와 전원 차단
- `include/`: 각 모듈의 헤더. Google 포맷은 `.clang-format`에 설정되어 있다.

`mk1_arm`과 비교하기 쉽게 함수 이름과 구성을 맞췄다.
diagnosis는 `showLedStatus()`·`updateRxTxLed()`·`updateVoltageCheck()`·
`setPowerOn/Off()`·`getButtonPress()`를 사용한다.
sensor도 `initBumper()`·`initLED()`·`LedPinArray`와 멜로디 배열을 사용하며,
음표와 duration을 한 줄에 쓰는 구간은 참고 코드 포맷을 유지한다.
IMU는 `mk1_motor` 인터페이스를 참고하되 비동기 재보정과 실제 센서 스케일 환산을 유지한다.

범퍼는 `mk1_arm`과 동일하게 OLLO 포트 3·4를 사용한다.
사용자 LED 4개는 `BDPIN_GPIO_4/6/8/10`, 버튼은 OpenCR 내장 버튼 2개다.

<a id="section-2"></a>

## USB 제어 테이블

배열은 ID 1~9 순서이며, 값은 little-endian DYNAMIXEL 원시 단위다.
각 원소를 따로 쓰거나 배열 전체를 연속해서 쓸 수 있다.
주소는 9개 모터 기준이며 `mk1_arm`의 호스트 주소표와는 다르다.

| 주소 | 형식 | 기능 |
|---|---|---|
| 10 | uint32 | 가동 시간 ms (읽기) |
| 15 | bool | 호스트 연결 (읽기) |
| 16 | bool | 모터 9개 모두 정상 응답 (읽기) |
| 18 | int8 | 장치 상태: -2 전원 차단, -1 모터 연결 실패, 0 정상, 1 저전압 (읽기) |
| 19 | uint8 | Heartbeat, 값과 관계없이 쓰기마다 갱신 |
| 20~23 | bool × 4 | 사용자 LED 켜기·끄기 |
| 26~27 | bool × 2 | 버튼 눌림 (읽기) |
| 28~29 | bool × 2 | 범퍼 눌림 (읽기) |
| 42 | uint32 | 배터리 전압 × 100 (읽기) |
| 46 | uint32 | 배터리 잔량 % × 100, 0~10000 (읽기, 전압 기반 선형 추정) |
| 50 | uint8 | 부저: 0 종료음, 1 시작음, 2 저전압음, 3 오류음 |
| 59 | bool | 전체 토크 설정, 마지막 성공한 요청 상태 |
| 60 | int32 × 9 | 목표 위치 버퍼 |
| 96 | bool | 1을 쓰면 목표 위치 전체 적용 |
| 97 | int32 × 9 | 현재 위치 (읽기) |
| 133 | int32 × 9 | 현재 속도 (읽기) |
| 169 | int16 × 9 | 현재 전류 (읽기) |
| 187 | uint32 × 9 | Profile Acceleration 버퍼 |
| 223 | bool | 1을 쓰면 가속도 전체 적용 |
| 224 | uint32 × 9 | Profile Velocity 버퍼 |
| 260 | bool | 1을 쓰면 속도 프로파일 전체 적용 |
| 261 | bool | 1을 쓰면 자이로 재보정 시작, 요청 후 0으로 복귀 |
| 262 | uint8 | IMU 상태: 0 초기화·보정 실패, 1 보정 중, 2 준비 완료 (읽기) |
| 264 / 268 / 272 | float × 3 | 각속도 X/Y/Z, rad/s (읽기) |
| 276 / 280 / 284 | float × 3 | 가속도 X/Y/Z, m/s², 중력 포함 (읽기) |
| 288 / 292 / 296 / 300 | float × 4 | 자세 쿼터니언 W/X/Y/Z (읽기) |

1. Heartbeat를 500ms보다 짧은 주기(예: 100ms)로 쓴다.
2. 주소 16이 1인지 확인하고 주소 59에 1을 쓴다. 현재 위치로 목표를 맞춘 뒤 토크를 켠다.
3. 필요하면 프로파일 배열을 쓰고 해당 적용 주소에 1을 쓴다. 버퍼 초기값 0은 모터의 실제 설정값을 뜻하지 않는다.
4. 주소 60에 목표 위치 9개를 쓰고 주소 96에 1을 쓴다. 적용 플래그는 성공 후 0으로 돌아간다.

부팅 시 토크는 꺼져 있다. 상태는 20ms 주기로 조회한다.
Heartbeat가 500ms 끊기면 새로 읽은 현재 위치를 목표로 보낸다.
모터 응답이 누락되거나 위치 유지 명령 전송이 실패하면 전체 토크 OFF를 시도한다.
초기 모터 설정이 실패하면 연결·전원을 확인하고 보드를 재시작한다.
Sync Write 성공은 패킷 전송 성공이며 개별 모터의 명령 수락을 보증하지 않는다.

배터리는 `mk1_arm`과 같은 3셀 기준이다. LED는 11.1V 미만에서 켜지고,
전압 진단은 약 100ms마다 수집한 10개 샘플 평균으로 약 1초마다 진행한다.
참고 코드처럼 `OFF → STARTUP → NORMAL → CHECK → WARNNING` 순서로 판단한다.
11.0V 미만이면 CHECK에 진입하고, 5회의 추가 확인 뒤에도 낮으면 WARNNING으로 넘어간다.
WARNNING에서는 약 2초 간격으로 1000Hz·500ms 경고음을 낸다.
이때 일반 멜로디는 중단하고 주소 50의 소리 요청은 거부하여 부저 충돌을 막는다.
WARNNING 상태에서 평균 전압이 10.5V 미만이면 DYNAMIXEL 전원을 차단한다.
따라서 차단 시간은 평균 필터와 현재 상태에 따라 달라지며, 이전의 고정 5초 방식과 다르다.
차단 후에는 배터리를 분리·재연결해도 보드를 재시작하기 전까지 전원과 모터 제어를 복구하지 않는다.
USB 전원만 연결되어 처음부터 전압이 5V 이하이면 OFF 상태에서 대기한다.
전압 임계값은 `include/xSting.h`, 확인 횟수와 상태 전이는 `src/diagnosis.cpp`에 있다.
배터리 잔량은 10.5~12.3V를 0~100%로 환산하고 범위를 제한한다.

<a id="section-3"></a>

## IMU

OpenCR 내장 `IMU` 라이브러리를 사용한다. 부팅 시 자동 자이로 보정이 실행되므로
보드를 움직이지 않는다. 라이브러리의 초기화는 최대 약 5초간 보정을 기다린다.
각속도·가속도는 라이브러리의 `gRes`·`aRes`로 환산한다.
축은 OpenCR IMU 좌표계이며, 로봇에 장착한 방향에 따른 좌표 변환은 호스트에서 한다.
쿼터니언은 가속도·자이로 기반이므로 yaw는 절대 방위가 아니며 드리프트할 수 있다.

IMU 업데이트는 메인 루프마다 호출한다(라이브러리 내부 최대 200Hz, 실제 주기는
모터 통신 시간에 따라 달라짐). USB 측정값은 기존 센서와 함께 20ms 주기로 갱신한다.
호스트는 주소 262가 2일 때 측정값을 사용한다. 보정 중이거나 실패한 경우에는
마지막 정상값을 유지하며, 정상 측정 전 초기값은 0이다.

재보정은 보드를 정지시킨 상태에서 주소 261에 1을 쓴다.
메인 루프에서 보정을 진행하므로 USB 통신·Heartbeat 감시·모터 처리는 계속된다.
5초 내 완료되지 않으면 상태가 0이 되며 다시 재보정을 요청할 수 있다.
상태 2는 초기화·보정 완료를 의미하며 실행 중 모든 센서 통신 오류를 검출하는 값은 아니다.
